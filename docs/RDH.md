# 可逆图像隐写（RDH）实现与验证

## 实现范围

主页面 `/applications/robustness` 已改为“可逆图像隐写”，支持秘密文本、任意二进制秘密文件、可选 AES-256-GCM / ChaCha20-Poly1305，以及独立上传 RDH PNG 后提取秘密信息并恢复原始 RGB。复用已有 ISTG v1、scrypt、认证加密、任务队列、文件存储、图像上传及质量指标组件。

旧 `/api/restoration/prepare`、`/api/restoration/restore` 保留原行为，以兼容已有文件；新页面全部使用 `/api/rdh/*`。旧 JPEG 加完整残差方案不属于新 RDH 算法。

## 算法与可逆性

实现名称：**固定棋盘格四邻域预测误差直方图平移（checkerboard PEHS，RGB8，v1）**。

思想参考 [Ni 等人的直方图平移](https://web.njit.edu/~ansari/papers/06TCAS.pdf) 和 [Thodi、Rodríguez 的预测误差嵌入](https://pubmed.ncbi.nlm.nih.gov/17357732/)。本实现是便于验证的固定参考棋盘格变体，并非声称逐行复现某篇论文。

1. EXIF 方向归一化，再用 Pillow `convert('RGB')` 转为 `uint8` RGB。恢复目标是这个数组，不包含输入文件字节、EXIF、ICC、透明通道或调色板编码。
2. 外围一圈像素与内部奇数棋盘格保持不变。只在内部偶数棋盘格嵌入，按 R、G、B 通道及行优先顺序扫描。
3. 对待嵌入样本计算 `prediction = (up + down + left + right + 2) // 4`，误差 `e = pixel - prediction`。预测值的邻居都不会被修改，提取时可精确重算。求和、误差和平移均使用 `int16`，避免 RGB8 整数溢出。
4. 每个通道分别评估向上、向下两个方向。向上跳过原值 255，向下跳过原值 0，用压缩二值位置图记录这些边界位置。跳过以后，向上的误差 +255、向下的误差 -255 必为空，因此总能找到相应方向的空闲误差值。
5. 在安全样本直方图中选最高峰 `p`，寻找该方向最近的空闲值 `z`。容量相同时优先选择平移像素更少、边界图更少的候选。
6. 若 `z > p`，将 `(p,z)` 内误差加 1，在峰值样本写入 `p` 或 `p+1` 表示秘密位 0/1；若 `z < p`，对称地减 1，写入 `p` 或 `p-1`。每个像素通道最多改变 1 个色阶。
7. 每通道仅使用记录长度对应的峰值样本保存秘密位；其余峰值仍为 `p`。因相邻误差槽已被腾空，提取不会把其他误差混淆为秘密位。
8. 提取时重算同一预测值，先读出峰值及其相邻槽中的位，将其恢复为 `p`，再逆向撤销区间平移。边界图还必须与恢复后的 0/255 位置完全一致。

只有一个嵌入棋盘格、没有多轮依赖，也没有修改预测参考像素。因此三通道容量与秘密位取值无关，分析阶段可以准确计算，不需要估算下一轮峰值。

## 容量和辅助信息

- **理论容量**：每通道原始预测误差直方图的最高峰数量之和，尚未排除不安全边界样本。
- **安全容量**：排除边界样本后实际选择的峰值数量之和。
- **有效像素载荷容量**：安全容量向下按整字节对齐。该容量容纳完整 ISTG 包。
- **有效秘密容量**：有效像素载荷字节数减去本次实际 ISTG 封装及加密开销。文件名长度、文件 SHA-256 字段、认证标签、KDF 元数据等均计入。
- **嵌入位数 / bpp**：实际 ISTG 包的总位数及其除以图像像素数后的值，不把无载荷像素算成已嵌入信息。

PNG 私有辅助块为 `rdHR`（私有、附加、编辑后不可安全复制）。其内容为 `RDH1` 标记加严格 CBOR：版本、尺寸、包长度、通道峰值/空闲值、通道使用位数、压缩边界位置图，以及包/原始 RGB/隐写 RGB 的 SHA-256。

**辅助块不包含秘密正文、原图像素或完整残差。秘密包全部嵌入像素。** 边界图只标记被跳过的 0/255 样本位置，不能代替原图。辅助字节数包含 PNG 块的 12 字节开销，位置图的压缩字节数另外展示。

这里选择外置必要辅助块，因此它不占像素槽，不从像素载荷容量重复扣减。页面明确区分像素容量、ISTG 开销和 PNG 辅助大小，避免把理论容量或外置元数据错误当成秘密容量。移除辅助块将无法恢复。

## 验证与错误处理

嵌入阶段先验证 ISTG 封装/解密后的秘密字节与用户输入相同。写出完整 PNG 后，立即调用提取流程重新解析 PNG、提取实际像素中的包，并执行：

```python
assert extracted_packet == original_packet
assert np.array_equal(original_rgb, restored_rgb)
```

这两个比较通过才发布文件。对外的秘密成功状态还依赖 ISTG 实际内容往返比较，不能仅由“没有抛异常”决定。

独立提取阶段校验所有 PNG 块 CRC、尺寸/颜色格式/动画标记、单个辅助块的位置、严格 CBOR 结构、哈希格式、各通道参数、位数、压缩位置图的确切解压长度与尾部填充，再校验隐写 RGB、提取包及恢复 RGB 的 SHA-256。加密包还必须通过认证解密和 ISTG 内容校验。任何失败不发布秘密文件或恢复图；多文件保存失败会回滚已保存的部分结果。

SHA-256 用于检查完整性，不表示图像来源经过签名；可选认证加密保护秘密数据。输出校验状态分别为“秘密数据完整恢复：通过”和“原始RGB像素精确恢复：通过”。

提取函数只有 PNG 字节参数，不访问原图、数据库或嵌入阶段缓存。测试实际删除全部文件与任务记录、创建另一服务会话，并在单独 Python 进程中仅凭 RDH PNG 完成恢复。

## API

| 接口 | 请求 | 行为 |
|---|---|---|
| `POST /api/rdh/uploads` | multipart `file` | 秘密文件上传，最大 4 MiB，可为空文件 |
| `POST /api/rdh/capacity` | JSON `image_id`、`text` 或 `secret_id`、`encryption` | 202，异步计算真实包长度与容量；加密探测包不用于正式嵌入 |
| `POST /api/rdh/embed` | 上述字段，可选 `password`、`confirm_password` | 202，嵌入、完整自校验及发布原始 RGB 预览和 RDH PNG |
| `POST /api/rdh/extract` | multipart `file`、可选 `password` | 202，提取、解密、校验，发布秘密文件和恢复 RGB PNG |

继续使用 `/api/tasks/{id}`、文件下载、任务删除及 JSON 报告导出接口。请求口令不写入任务结果或报告，任务结束清除请求对象的口令/正文引用。原始文件与处理结果仍按本地系统既有临时存储机制管理。

## 限制

- 单棋盘格和每通道单峰避免复杂的多轮依赖，优先保证可验证性；随机/高噪声图像的误差分布较平，实际容量可能很低。
- 原图最大 16 MiB、1600 万像素；RDH 输出/提取最大 96 MiB，秘密文件上传最大 4 MiB；最终还必须通过图像实际容量检查。
- 辅助块必须保留，PNG 不是任意编辑后仍可提取的鲁棒水印。尺寸、像素或必要辅助信息被改动时应拒绝恢复。
- 可逆性不等于压缩率、隐写不可检测性或图像来源认证；辅助位置图和 PNG 文件开销会随图像分布变化。
