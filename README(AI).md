# ISTG Studio

## 工程结构与运行

- `istg/`：信息预处理、数据封装与隐写算法。
- `backend/`：后端服务，处理请求并调用算法。
- `frontend/`：网页界面代码。
- `requirements.txt`：运行依赖清单。

在项目根目录安装依赖并运行：

```bash
python -m pip install -r requirements.txt
python run.py
```

当前在本地运行，后续可另行配置服务器部署。

## 图像隐写流程

1. 输入秘密信息和载体图片。
2. 进行信息编码与预处理。
3. 使用 CBOR 编码数据。
4. 构建 ISTG v1 数据包。
5. 按需加密数据包中的有效载荷。
6. 使用选定的隐写算法嵌入载体图片。
7. 输出隐写图片。

## 安全性分析

观察隐写前后的图片差异，展示统计结果与评价指标。

1. **自动提取分析**：按算法和参数候选尝试提取，加密数据需提供密码解密。
2. **位平面可视化**：查看隐写前后的位平面变化。
3. **隐写痕迹检测**：展示相关统计结果。
4. **性能评价**：输出指标，比较算法表现。
5. **鲁棒性测试**：观察 JPEG 压缩或噪声处理后的信息恢复情况。

## 新增功能

1. **多模态隐写**：增加音频、视频和文本载体，支持隐藏与提取秘密文字或文件。用于比较不同载体的隐写效果，以及压缩、噪声等处理对恢复结果的影响。
2. **网络隐写**：支持在网络通信中传递隐藏文字，并查看流量与恢复结果。另提供双机文件传输，用于网络隐写与信息传输。
3. **SecretVideo 通话**：支持 2–4 人音视频通话，在视频帧中传递加密的群聊、私聊文字和小文件。也可将语音识别为文字后隐藏发送，用于演示实时通话中的信息隐藏。

## 应用场景

首页与顶部“应用场景”菜单提供三个入口：

- `/applications/medical`：影像信息嵌入。填写文字、记录编号与备注，嵌入图像后提取核验；支持可选加密与画质比较。
- `/applications/robustness`：压缩图像高清恢复。生成 JPEG 压缩预览，将恢复信息内嵌到同一张 PNG，下载后只用该文件即可恢复原始 RGB 像素。结果展示原文件、预览、恢复层及最终文件大小。
- `/applications/copyright`：数字版权保护。提供真实账户、作品管理、签名版权标识、分发记录验证，以及按用户设置的查看、下载、有效期和撤销授权。

高清恢复使用自定义恢复层，按 [PNG 规范的私有附加块机制](https://www.w3.org/TR/png-3/#5Chunk-naming-conventions)存储。恢复目标是经过 EXIF 方向归一化的 RGB 像素，使用像素 SHA-256 校验；原文件字节、透明通道与其他元数据不在恢复范围内。恢复层会增加文件体积，最终大小不保证小于输入。普通 JPEG 或移除了恢复层的图像不能用于该恢复流程。原有压缩、噪声、裁剪等鲁棒性测试保留在“安全分析 → 性能与鲁棒性”中。

版权标识使用 [Ed25519 数字签名](https://www.rfc-editor.org/rfc/rfc8032)，并绑定图像尺寸与 RGB 高七位摘要；平台公钥和分发记录共同用于验证。标识签名、图像绑定、记录匹配分别展示，不将署名声明作为版权归属证明，也不宣称压缩或裁剪后必然保留标识。

版权原图与分发图使用 AES-GCM 加密保存，不进入公共临时文件下载接口。访问检查参照 [OWASP 授权建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)，在每次请求时检查账户、作品归属和授权状态；撤销或到期会阻止后续访问，已经交付的明文无法收回。

版权账户、作品、授权记录和加密／签名密钥默认持久保存在 `.copyright-data/`，重启后保留。可用环境变量 `ISTG_COPYRIGHT_DIR` 指定目录。备份时应保留整个目录；不要将该目录作为代码包分发，丢失密钥将无法读取旧作品或验证旧标识。其他上传与处理结果仍按原有临时文件机制管理。

跨页只传递内存中的结果标识和非敏感参数。密码与散布位置密钥不写入 URL 或浏览器本地存储，刷新后需重新上传。

## 数据封装

自定义的 **ISTG v1** 数据包分为三部分：

- **Header（固定头部）**：20 字节，记录协议标识、版本、算法和参数字段、数据长度及 CRC32 校验码。
- **Metadata（元数据）**：可变长度，使用 CBOR 编码，记录数据格式、加密相关参数等信息。
- **Payload（有效载荷）**：可变长度，保存文本、图片等信息的 CBOR 编码结果，或加密后的密文。

具体字段以代码为准，修改时应保持封装与解析一致。
